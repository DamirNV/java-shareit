# Java ShareIt — сервис обмена и бронирования вещей

**Java ShareIt** — учебный backend-проект на Java и Spring Boot, в котором пользователи могут делиться вещами, находить нужные предметы и бронировать их на определённое время.

Приложение позволяет владельцам публиковать вещи и управлять заявками на бронирование. Другие пользователи могут искать доступные предметы, отправлять запросы на аренду, создавать запросы на отсутствующие вещи и оставлять отзывы после завершённого бронирования.

Проект реализован в рамках обучения Java-разработке в Яндекс Практикуме. Он демонстрирует разработку REST API, работу с реляционной базой данных, разделение приложения на компоненты, валидацию запросов и тестирование.

## Возможности

- **Пользователи:** создание, получение, изменение и удаление учётных записей.
- **Вещи:** добавление и изменение предметов, просмотр вещей владельца, поиск доступных вещей по названию и описанию.
- **Бронирования:** создание заявки на определённый период; подтверждение или отклонение заявки владельцем; просмотр собственных бронирований и бронирований своих вещей.
- **Статусы бронирований:** фильтрация по состояниям `ALL`, `CURRENT`, `PAST`, `FUTURE`, `WAITING`, `REJECTED`.
- **Отзывы:** добавление комментария к вещи после завершённого подтверждённого бронирования.
- **Запросы вещей:** публикация запроса на отсутствующий предмет, получение собственных и чужих запросов, просмотр вещей, добавленных в ответ на запрос.
- **Проверка данных и прав:** валидация DTO, проверка владельца вещи и доступности бронирования, обработка ошибок HTTP.

Приложение предоставляет REST API, а не веб-интерфейс. Полноценная авторизация с паролями или токенами не реализована: идентификатор пользователя для части запросов передаётся через HTTP-заголовок `X-Sharer-User-Id`.

- **Spring Data JPA / Hibernate** — сущности и репозитории
- **PostgreSQL 15** — основное хранилище данных
- **H2** — база данных для тестового профиля
- **Maven** — многомодульная сборка
- **RestTemplate / Apache HttpClient 5** — HTTP-взаимодействие между компонентами
- **Lombok** — сокращение шаблонного Java-кода
- **Docker / Docker Compose** — контейнеризация приложения и PostgreSQL
- **JUnit 5, Mockito, Spring Test, @DataJpaTest** — тестирование
- **Checkstyle, SpotBugs, JaCoCo** — дополнительные Maven-профили контроля качества
- **GitHub Actions** — автоматическая сборка и тестирование

## Архитектура

Приложение состоит из двух модулей:

```text
HTTP-клиент
    |
    v
Gateway :8080
    |
    | Валидация запросов, DTO, RestTemplate
    v
Server :9090
    |
    | Контроллеры, сервисы, репозитории
    | Spring Data JPA / Hibernate
    v
PostgreSQL :5432
```

**Gateway** принимает внешние HTTP-запросы, проверяет входные данные и передаёт запросы в Server.

**Server** реализует предметную логику бронирования, управления вещами и пользователями. Для хранения данных используются JPA-репозитории и PostgreSQL.

Схема таблиц создаётся из `server/src/main/resources/schema.sql`.

Основные сущности:

- `User` — пользователь;
- `Item` — вещь;
- `Booking` — бронирование;
- `Comment` — отзыв;
- `ItemRequest` — запрос на вещь.

## REST API

Базовый адрес Gateway после запуска:

`http://localhost:8080`

| Метод | Маршрут | Назначение |
|---|---|---|
| GET | `/users` | Получить всех пользователей |
| POST | `/users` | Создать пользователя |
| GET | `/users/{id}` | Получить пользователя |
| PATCH | `/users/{id}` | Изменить пользователя |
| DELETE | `/users/{id}` | Удалить пользователя |
| GET | `/items` | Получить вещи владельца |
| POST | `/items` | Добавить вещь |
| GET | `/items/{itemId}` | Получить вещь |
| PATCH | `/items/{itemId}` | Изменить вещь |
| GET | `/items/search?text=...` | Поиск вещей |
| POST | `/items/{itemId}/comment` | Добавить отзыв |
| POST | `/bookings` | Создать бронирование |
| GET | `/bookings` | Получить свои бронирования |
| GET | `/bookings/{bookingId}` | Получить бронирование |
| PATCH | `/bookings/{bookingId}?approved=true` | Подтвердить бронирование |
| GET | `/bookings/owner?state=ALL` | Бронирования вещей владельца |
| POST | `/requests` | Создать запрос на вещь |
| GET | `/requests` | Получить свои запросы |
| GET | `/requests/all` | Получить чужие запросы |
| GET | `/requests/{requestId}` | Получить запрос по ID |

Для некоторых маршрутов требуется заголовок `X-Sharer-User-Id` с идентификатором пользователя.

### Примеры запросов

**Создание пользователя:**

```bash
curl -X POST http://localhost:8080/users \
  -H 'Content-Type: application/json' \
  -d '{"name":"Иван","email":"ivan@example.com"}'
```

**Добавление вещи:**

```bash
curl -X POST http://localhost:8080/items \
  -H 'Content-Type: application/json' \
  -H 'X-Sharer-User-Id: 1' \
  -d '{
    "name":"Дрель",
    "description":"Аккумуляторная дрель",
    "available":true
  }'
```

**Поиск вещей:**

```bash
curl 'http://localhost:8080/items/search?text=дрель'
```

**Создание запроса на вещь:**

```bash
curl -X POST http://localhost:8080/requests \
  -H 'Content-Type: application/json' \
  -H 'X-Sharer-User-Id: 1' \
  -d '{"description":"Нужен проектор на выходные"}'
```

**Удаление пользователя:**

```bash
curl -X DELETE -i http://localhost:8080/users/1
```

В примерах предполагается, что приложение запущено и пользователь с ID 1 создан.

## Запуск приложения

### Требования

- JDK 21
- Maven 3.9+
- Docker и Docker Compose
- Свободные порты 8080, 9090 и 5432

### Вариант 1. Локальный запуск

Сначала запустите PostgreSQL через Docker:

```bash
docker compose up -d postgres
```

В первом терминале из корня проекта:

```bash
cd server
mvn spring-boot:run
```

Во втором терминале из корня проекта:

```bash
cd gateway
mvn spring-boot:run
```

После запуска:

- Gateway — `http://localhost:8080`
- Server — `http://localhost:9090`
- PostgreSQL — `localhost:5432`

Проверка доступности API:

```bash
curl http://localhost:8080/users
```

### Вариант 2. Запуск через Docker Compose

В конфигурации Gateway используется переменная окружения `SHAREIT_SERVER_URL`, позволяющая указать адрес Server.

Для контейнерного окружения:

```text
SHAREIT_SERVER_URL=http://server:9090
```

Для локального запуска по умолчанию:

```text
http://localhost:9090
```

Соберите приложение из корня репозитория:

```bash
mvn clean package -DskipTests
```

Запустите контейнеры:

```bash
docker compose up --build
```

После запуска API должен быть доступен по адресу:

`http://localhost:8080`

Для остановки контейнеров:

```bash
docker compose down
```

**Примечание:** Docker Compose задаёт порядок запуска сервисов, но без healthcheck не гарантирует готовность PostgreSQL к моменту подключения Server.

Полный запуск всех контейнеров после исправлений отдельно не подтверждён.

## Тестирование

В проекте содержится **62 тестовых метода JUnit 5**:

- **46 тестов Gateway** — проверка контроллеров, валидации и DTO.
- **16 тестов Server** — проверка JPA-репозиториев с использованием тестового профиля H2.

Запуск тестов из корня проекта:

```bash
mvn test -Dspring.profiles.active=test
```

Для отдельных модулей:

```bash
cd gateway
mvn clean verify
```

```bash
cd server
mvn clean verify -Dspring.profiles.active=test
```

### GitHub Actions

В репозитории настроена автоматическая проверка Java CI with Maven.

Workflow:

1. Загружает исходный код.
2. Устанавливает JDK 21.
3. Собирает и тестирует Gateway.
4. Собирает и тестирует Server с профилем H2.

**Результат:** проверка [Java CI with Maven #11](https://github.com/DamirNV/java-shareit/actions/runs/45345548146) успешно завершилась после внесения исправлений в проект.

Это подтверждает прохождение Maven-проверок в данном запуске, но не заменяет отдельную проверку работы Docker Compose.

### Проверка качества кода

В Maven предусмотрены дополнительные профили:

```bash
mvn verify -Pcheck
```

Проверка Checkstyle и SpotBugs.

```bash
mvn verify -Pcoverage
```

Создание отчёта JaCoCo.

Успешность отдельного выполнения этих профилей не подтверждена.
